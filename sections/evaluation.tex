\section{Preliminary Results}
\label{sec:eval}

We implement a prototype of \sys in Rust, with Bullshark~\cite{bullshark} as the consensus component.
Here we present preliminary results of \sys comparing to a fully replicated baseline BFT store.
We plan to conduct more comprehensive evaluations in the full version of the paper, including comparisons with Basil and sharded blockchains, and measuring more performance metrics such as latency and scalability with more shards and nodes.

In our preliminary evaluation, we deploy \sys and the baseline on 100 nodes.
The state is a 100 GB key-value store with 100 million keys.
In the baseline, each node stores the full state, while in \sys the state is sharded into 100 partitions, each stored on a node shard of 7 shards.
The node shards are overlapped for better load balancing, and each shard can tolerate up to 2 Byzantine nodes.

In the evaluation, we run a read-only YCSB workload to stress \sys under a high network fetch load, which is the worst case for \sys.
We also test different workload skews to understand the impact of caching, ranging from uniform ($\alpha=0$) and highly skewed ($\alpha=1.24$).
The results are shown in \cref{fig:skew-tput}.
Unsurprisingly, \sys constantly outperforms the baseline in all scenarios with and without caching and under both uniform and skewed workloads, because \sys parallelizes state access and significantly reduces the number of overall disk access.
In the baseline, every state access translates to 100 disk accesses across the 100 nodes, while in \sys only 7 nodes need to access the disk for it.
Furthermore, due to caching, the performance of both systems improves as the workload becomes more skewed.
\sys can achieve the throughput of 350k transactions per second under a skewed workload, 1.14 times higher than the baseline.

Unfortunately, the current implementation of \sys is not optimized and the performance scalability has not been fully realized, so the performance improvement over fully replicated baseline and previous works is not as significant as we expect.
In the future, we will apply the optimizations described in \cref{sec:overview} and expect to see the performance of \sys to scale with the number of nodes and significantly outperform the other systems.
