Blockchain state is growing big.
The popular permissionless blockchains are incurring hundreds to thousands of GBs states, and the high storage requirements to run nodes have been causing centralization.
On the other hand, big data applications are vastly deploying on to blockchains, whose states can scale up to TB or even PB level.
Eventually, the node storage are not going to be on par with the state size and the blockchains must be able to operate with nodes holding partial states.

Sharded blockchains are extensively studied by the previous works.
While these works indeed allow nodes to store only part of the states, the consequence is that not all nodes can process all transactions.
As the result, these works cannot retain the standard security guarantee of blockchains \ie Byzantine faulty tolerance (BFT) replication: deterministically tolerate any $f$ Byzantine faulty nodes with a total of at least $3f+1$ nodes.
Some works degrade to tolerate only $\frac{1}{4}$ faulty nodes, some resorts to probabilistic safety guarantee, while the others demand predetermined node \emph{committees} and can only tolerate $\frac{1}{3}$ Byzantine faults locally within each committee.

As in regular databases, the storage layer shards the state and each node preserves only a subset of the shards.
At the same time, the global consensus (\ie Byzantine atomic broadcast) and processing are retained, and the accessed shards are made available by the storage layer prior to transaction processing on all nodes, create the ``illusion'' of the shards are stored by every node.
Thus, the sharding design is fully \emph{decoupled} with the consistency guarantee and only need to ensure the availability of state shards.

We emphasize that this \emph{separation of concern} is crucial to escape the dilemma between scalability and safety, allowing us to independently scaling out the state without affecting the consistency guarantee of BFT protocols.

To this end, we propose \sys, a BFT protocol with optimal resiliency to Byzantine faults, ensuring consistency and availability with constant redundancy.
To cope the Byzantine storing nodes, we deploy erasure code to disseminate the state shards to more than $\frac{2}{3}$ of all the nodes with a constant overall redundancy (\ie about 3x).

While erasure code space-efficiently spread shards to a wide range of the nodes, performing encode and decode operations online significantly affect performance.
So we propose an alternative online processing path with constant number of verbatim copies of state shards residing on uniformly random nodes.
This processing path is free to encode and decode and achieve probabilistic (but tunable) availability.

Both of the methods incurs constant overall storage overhead.
With more nodes joining the system, the storage consumption for storing the state remains unchanged, and the nodes can collaboratively store larger state with increasing storage capacity.

\sys combines the two aforementioned methods, utilizing the verbatim copies as the \emph{active layer} and the erasure code as the \emph{archive layer}.
The active layer possesses the latest version of the state shards and can serve online processing with high probability.
At the same time, \sys periodically archives the state with erasure code, providing deterministic safety guarantee with minimal overhead.
