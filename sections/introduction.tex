Prevailing permissionless distributed ledgers~\cite{buterin2014next, nakamoto2008bitcoin} present state size spanning hundreds to thousands of gigabytes (\autoref{fig:states-grow}), exposing considerable financial burden to nodes replicating the states and rendering on-chain data storage economically unviable~\cite{balduf2022dude}.

Simultaneously, the implementation of extensive data applications on blockchain platforms is experiencing notable growth~\cite{qi2021bidl,lokhava2019fast,bodkhe2020blockchain,liu2018blockchain,xu2018making,kim2021two,jeong2020design,sun2020blockchain,li2019edurss,shen2019secure,salah2019blockchain,hirtan2018blockchain, sharma2018blockchain}, with state magnitudes frequently attaining terabyte or petabyte scales~\cite{laughlin2014information,rabindrajit2024high,pollard2018eicu,johnson2023mimic}.
Large-scale deployments of permissioned and consortium blockchains, encompassing hundreds to thousands of nodes and frequently considered in prior investigations~\cite{kokoris2018omniledger,zamani2018rapidchain,amiri2021sharper,gilad2017algorand,gueta2019sbft,yin2019hotstuff}, will impose substantial storage requirements at each node if the state is fully replicated.
Addressing this challenge requires the achievement of \emph{storage scalability}:

the storage consumption on each node must decrease proportionally to the increase of node count.
Only by realizing storage scalability, the storage resource contributed by the newly-joined nodes can help blockchains to operate larger state size.

Sharded blockchains, wherein nodes can function by maintaining only a segment of the state, have been the subject of considerable prior research~\cite{ruan2021blockchains,luu2016secure,kokoris2018omniledger,dang2019towards,zamani2018rapidchain,wang2019monoxide,amiri2021sharper}.
Although these endeavors attain scalable storage requirements, they introduce compromises between storage scalability and security attributes, specifically safety and liveness~\cite{pbft}.
Consequently, these approaches fail to uphold the conventional security assurance of blockchains, also known as Byzantine fault tolerance (BFT)~\cite{bft} replication, which deterministically accommodates any $f$ Byzantine faulty nodes within a total of $3f+1$ nodes.
They may rely on probabilistic safety guarantees, proposing to tolerate only $\frac{1}{4}$ faulty nodes~\cite{luu2016secure,kokoris2018omniledger} or impose supplementary prerequisites such as trusted hardware~\cite{dang2019towards} or synchronous networks~\cite{zamani2018rapidchain}.
Other solutions necessitate pre-defined fault-tolerant clusters and can only manage $\frac{1}{3}$ Byzantine faults locally within each committee~\cite{ruan2021blockchains,amiri2021sharper,gupta2020resilientdb}.
Ultimately, no prior sharding method achieves storage scalability without impacting safety and liveness properties.

The trade-off between security and scalability arises from the prevalent \emph{processing sharding} methodology employed by prior research, as depicted in \autoref{fig:approach-compare}.
The entirety of processing, encompassing consensus and execution, is partitioned, with only a limited set of nodes (\ie, the committee) involved in transaction processing.
This leads to diminished resilience against safety and liveness attacks.
% Conversely, storage scalability is attained by partitioning the state, without necessitating the fragmentation of other components \lijl{what does this sentence mean?}.

We observe that only the sharding of the state is crucial for blockchains to achieve storage scalability, while sharding the other components is unnecessary while posing undesirable consequences.
Based on this observation, we introduce a novel approach: we decouple a state management system (SMS) from the execution layer to handle a sharded state, while maintaining global consensus and execution layers.
This innovative methodology achieves a clear \emph{separation of concerns}: the SMS solely addresses storage scalability and availability, which can be effectively managed using advanced erasure coding~\cite{ec} techniques.
Concurrently, the consensus and execution layers can focus on security attributes without concerns about impacting storage scalability.

We present a novel SMS that ensures availability with scalable storage, whose architecture comprises two tiers.
The archive layer utilizes erasure coding to offer a deterministic availability guarantee.
The active layer maintains a fixed number of shard replicas on a randomized node group, ensuring efficient access with high probability.
